# M4: OAuth + MCP + README Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** v1 complete: bring-your-own-app OAuth login (`ynab auth login --oauth`, scope=read-only, localhost redirect, rotating refresh tokens), `ynab mcp serve` (rmcp, stdio) exposing the same core functions as the CLI, a README with the registration walkthrough, and the accumulated carry-over fixes.

**Architecture:** OAuth lives in `src/auth/` (new module family; the `oauth2` crate performs the token-endpoint POST internally — our code still contains no HTTP write verb, and `src/api/client.rs` stays GET-only). Token resolution becomes YNAB_PAT env → keychain PAT → OAuth access token with refresh-when-stale (expiry stored beside the access token; refresh tokens rotate — ALWAYS store the newest). The MCP frontend is a thin adapter: each tool call builds a fresh `Ctx` and returns exactly the raw JSON envelope that `--json` prints — per-call semantics identical to a CLI invocation, sidestepping the Connection-not-Sync issue.

**User rulings baked in:** logout clears tokens + OAuth app creds + cache DB (and siblings) + cache key. All prior rulings stand.

**Tech Stack:** `oauth2` (already a dep, v5), `rmcp` (new — official Rust MCP SDK; version note below), `webbrowser` (best-effort browser open), `zeroize` (carry-over polish), `tiny_http`? NO — the redirect listener is a hand-rolled `std::net::TcpListener` loop (one request, no dependency).

**API-uncertainty note (Tasks 1 and 3):** the `oauth2` v5 and `rmcp` crate APIs move fast. The code below is the SHAPE contract (function names, behavior, tests); if the crate API differs, adapt minimally, consult docs (context7/docs.rs) rather than guessing, and record every adaptation in your report. Behavior specs and tests are binding; exact crate-API incantations are not.

## Global Constraints

- **Read-only stays structural for budget data**: no HTTP write verb anywhere in OUR code; `src/api/client.rs` unchanged in this respect. The oauth2 crate's internal POST targets only `app.ynab.com/oauth/token` (documented nuance in CLAUDE.md).
- **OAuth always requests `scope=read-only`** — server-side enforcement; a missing scope param is a spec violation.
- **No secrets on disk, in output, or in the repo**: client_id/client_secret/access/refresh tokens live only in the keychain (`SecretKind::OauthClientId/OauthClientSecret/OauthAccessToken/OauthRefreshToken`); never printed, never logged, never in error messages.
- **Refresh tokens are single-use and rotate** — after every refresh, store BOTH the new access token (with expiry) AND the new refresh token before using them.
- **Tests never touch the real keychain, network, browser, or dirs** (mock keyring; wiremock for the token endpoint; browser-open suppressed via env `YNAB_CLI_NO_BROWSER`).
- No `.unwrap()`/`.expect()` on fallible paths in non-test code. Commits conventional, no attribution trailers. Gate: build/test/clippy `-D warnings`/fmt clean.

### Task 1: OAuth core (flow, exchange, refresh, storage)

**Files:**
- Create: `src/auth/mod.rs`, `src/auth/oauth.rs`, `src/auth/listener.rs`
- Modify: `src/lib.rs` (add `pub mod auth;` — NOTE: name collision check — `src/cli/auth.rs` is `cli::auth`, this is crate-level `auth`; fine), `Cargo.toml` (add `webbrowser = "1"`; `oauth2` already present)

**Interfaces (binding shapes):**
- `auth::oauth::AppCredentials { pub client_id: String, pub client_secret: secrecy::SecretString }`
- `auth::oauth::get_or_prompt_app_credentials(store: &SecretStore, reset: bool) -> Result<AppCredentials>` — keychain first; prompts (stdin, visible for id / hidden for secret, same TTY/pipe handling as PAT login) and stores when missing or `reset`.
- `auth::oauth::login(store: &SecretStore, reset_app: bool) -> Result<()>` (async) — full flow: creds → CSRF state + authorize URL (`response_type=code&scope=read-only&redirect_uri=http://localhost:<port>/callback`) → print URL always; open browser best-effort unless env `YNAB_CLI_NO_BROWSER` set → `listener::wait_for_code(port, expected_state)` → exchange code at token endpoint → `store_tokens` → print `Logged in via OAuth. Access token valid for about 2 hours; it will refresh automatically.`
- `auth::oauth::store_tokens(store, access: &str, expires_in_secs: i64, refresh: &str) -> Result<()>` — OauthAccessToken entry holds JSON `{"access_token": "...", "expires_at": <unix_now + expires_in - 60>}`; OauthRefreshToken holds the raw refresh token.
- `auth::oauth::current_access_token(store: &SecretStore) -> Result<Option<secrecy::SecretString>>` (async) — None if no OAuth material; if access token unexpired (expires_at > now + 300) return it; else refresh via the token endpoint (`grant_type=refresh_token`), STORE ROTATED PAIR FIRST, return new access. Refresh failure ⇒ `Err(Error::NotAuthenticated)` (message tells the user to `ynab auth login --oauth`).
- `auth::listener::wait_for_code(port: u16, expected_state: &str) -> Result<String>` — one-shot `std::net::TcpListener` on 127.0.0.1:port; parses `GET /callback?code=...&state=...`; state mismatch ⇒ `Error::Config("OAuth state mismatch — try again")`; responds `200 text/html` "Authorized — you can close this tab." then returns the code. A `?error=access_denied` response ⇒ `Error::Config("authorization was denied")`.
- Time source: `std::time::SystemTime::now()` (unix secs helper `fn unix_now() -> i64`).

### Task 3: MCP server (`ynab mcp serve`)

**Files:**
- Create: `src/mcp/mod.rs` (and submodules if the rmcp API pushes that way)
- Modify: `src/lib.rs` (`pub mod mcp;`), `src/cli/mod.rs` (`Mcp { command: McpCommand }`, `McpCommand::Serve`, dispatch arm calling `crate::mcp::serve().await`), `Cargo.toml` (add `rmcp` with the stdio/server + macros features per its docs)

**Binding behavior:**
- `ynab mcp serve` runs an MCP server over stdio until the client disconnects.
- Five tools, mirroring the CLI exactly (names and descriptions binding):
  - `list_budgets` () — returns the raw budgets `data` envelope (same JSON as `ynab budgets list --json`).
  - `list_accounts`, `list_categories`, `list_payees` (optional `budget_id: string`) — budget resolution identical to the CLI: param → config default_budget → `last-used`; cache policy identical (cache unless `last-used`; silent fallback).
  - `list_transactions` (optional `budget_id`, `since`, `until`, `payee`, `account`, `category`, `uncategorized: bool`, `unapproved: bool`) — same normalization/validation (invalid date returns a tool error with the exact CLI message) and the transactions `--json` semantics (explicit filters only, deleted kept, envelope preserved).
- Implementation shape: each tool builds a per-call `Ctx` via a shared helper (`build_ctx(json=true-ish, budget_param.as_deref(), no_cache=false)` — reuse `cli::context::build_ctx` as-is), calls the same sync-or-direct path the CLI commands use, and returns the raw envelope as the tool's JSON result. Errors map to MCP tool errors carrying our `Error` display strings (never a token). Extract the CLI's fetch logic into small shared helpers ONLY where needed to avoid duplicating filter code — e.g. move the transactions raw-filtering block into a `pub(crate) fn filtered_raw_transactions(result, &Filters) -> serde_json::Value` in `src/cli/transactions.rs` and call it from both frontends.
- Server metadata: name `ynab-cli`, version from `env!("CARGO_PKG_VERSION")`, instructions string noting the server is absolutely read-only.
- Tests: handler-level — call the tool functions directly (not over stdio) against wiremock + tempdir envs, assert envelope JSON and error mapping; plus one `assert_cmd` smoke test that `ynab mcp serve` starts and exits cleanly when stdin closes (spawn with stdin piped-then-dropped, assert exit 0 within timeout — adapt if rmcp treats EOF differently; document behavior).

Steps: TDD; consult rmcp docs (docs.rs/context7) BEFORE writing the server — do not guess the macro API; commit `feat: MCP server with five read-only list tools`.
